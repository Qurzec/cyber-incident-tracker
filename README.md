# Лабораторна робота №5: Веб-застосунок "Трекер інцидентів кібербезпеки" (Варіант 2) - Безпека та Захист від вразливостей

Цей проєкт є інтегрованим веб-застосунком для реєстрації та відстеження інцидентів кібербезпеки, який складається з клієнтської частини (**Frontend** на TypeScript) та серверної частини (**Backend API** на TypeScript з SQLite), інтегрованих між собою через версійні HTTP REST-запити.

---

## Структура проєкту

Проєкт розділений на два основні компоненти:

* **[frontend/](file:///home/manjaro/projects/lab5/frontend/)**: Клієнтська частина застосунку (повністю переписана на **TypeScript**). Компілюється у статику в папку `public/js/` та взаємодіє з сервером через HTTP-запити (`fetch`).
* **[backend/](file:///home/manjaro/projects/lab5/backend/)**: Серверна часть (Node.js + Express + TypeScript + SQLite). Надає REST API з версійністю `/api/v1/` та захистом CORS.

---

## Як запустити застосунок

### Крок 1: Запуск Бекенд-сервера (API)

1. Перейдіть у папку `backend`:
   ```bash
   cd backend
   ```
2. Встановіть необхідні залежності:
   ```bash
   npm install
   ```
3. Запустіть ініціалізацію та наповнення бази тестовими даними:
   ```bash
   npx tsx src/db/seed.ts
   ```
4. Запустіть сервер у режимі розробки:
   ```bash
   npm run dev
   ```
   *Сервер запуститься за адресою: `http://localhost:3000`.*

### Крок 2: Запуск Фронтенду (UI)

1. Перейдіть у папку `frontend`:
   ```bash
   cd ../frontend
   ```
2. Встановіть залежності компилятора TypeScript:
   ```bash
   npm install
   ```
3. Скомпілюйте TypeScript-код:
   ```bash
   npm run build
   ```
4. Запустіть локальний веб-сервер для UI:
   ```bash
   npm start
   ```
   *Фронтенд запуститься за адресою: `http://localhost:5500`.*

## Реалізована функціональність (Лабораторна робота №5 - Рівень "На Відмінно")

Цей застосунок об'єднує в собі інтегрований функціонал попередніх робіт (включаючи типізований клієнт на TypeScript, CORS та версійність API з Лабораторної роботи №4) та комплексні засоби захисту від вразливостей з Лабораторної роботи №5.

### 1. Серверна частина (Backend):
* **Версійність API**: Всі ендпоінти перенесені під префікс версії `/api/v1/` (наприклад, `/api/v1/incidents`).
* **Безпека CORS**: Вимкнено загальний доступ через `*`. Налаштовано суворий список дозволених джерел (whitelist: `http://localhost:5500` та інші dev-порти), явно обмежені дозволені методи та заголовки, коректно обробляються OPTIONS preflight запити.

### 2. Клієнтська частина (Frontend):
* **Міграція на TypeScript**: Весь клієнтський код переписано на TypeScript з розподілом на модулі:
  - `config.ts` — константи налаштування.
  - `dtos.ts` — типізовані контракти запитів/відповідей та помилок.
  - `apiClient.ts` — ізольована робота з мережею та обробка помилок.
  - `ui.ts` — рендеринг та робота з DOM.
  - `main.ts` — сценарії та обробники подій.
* **Надійність та обробка збоїв**:
  - **Таймаути запитів**: Реалізовано автотаймаут запиту (10 секунд) та можливість ручного скасування з'єднання через кнопку «Скасувати запит» за допомогою `AbortController`.
  - **Стани інтерфейсу**: Реалізовано 4 стани для кожної мережевої дії: `loading` (крутилка), `success` (відображення таблиці), `empty` (повідомлення про відсутність результатів фільтрації) та `error` (помилка підключення або 4xx/5xx відповідь).
  - **Захист від подвійних кліків**: На час виконання запиту всі елементи форми та кнопки блокуються.
## Реалізована функціональність та Захист від вразливостей (Лабораторна робота №5)

### 1. Захист від SQL Injection (SQLi)
* **Запит параметризації**: Повністю відмовилися від конкатенації рядків та використання функції `escapeSql`. Всі запити в репозиторіях `UserRepository` та `IncidentRepository` переписано з використанням параметризованих плейсхолдерів (`?`).
* **Безпечний Пошук**: Метод `searchVulnerable` тепер також повністю захищено через параметризацію:
  ```typescript
  const sql = "SELECT * FROM Incidents WHERE comments LIKE ? ORDER BY id DESC;";
  const rows = await all<any>(sql, [`%${q}%`]);
  ```

### 2. Захист від збереженого XSS (Stored XSS)
* **Екранування на Фронтенді**: У `ui.ts` додано функцію `escapeHtml`, яка замінює небезпечні символи (як-от `<`, `>`, `&` тощо) на безпечні аналоги, щоб браузер не запускав їх як HTML-теги.
* **Безпечний Рендеринг**: При відображенні полів `reporter` та `comments` у таблиці дані екрануються перед вставкою в HTML, що робить спроби ін'єкції скриптів (`<script>alert(1)</script>`) повністю нешкідливими.

### 3. Захист від IDOR (Insecure Direct Object Reference)
* **Власник інциденту**: В схему бази даних додано стовпець `ownerUserId INTEGER NOT NULL REFERENCES Users(id)`.
* **Авторизація на бекенді**: Створено middleware `demoAuthMiddleware`, яке зчитує заголовок `X-Demo-UserId`, дістає відповідного користувача з БД та встановлює його у `req.user`.
* **Перевірка доступу**: При спробах створення, оновлення (PUT/PATCH) чи видалення (DELETE) інциденту, бекенд перевіряє, чи є поточний користувач власником інциденту (`existingIncident.ownerUserId === currentUserId`). У разі невідповідності повертається статус `403 Forbidden`.
* **Демонстрація перемикання користувачів**: На фронтенді зверху додано випадаючий список користувачів (David - Admin, Olena - Editor, Ivan - User). При виборі користувача його ID зберігається в `localStorage`, і всі наступні HTTP-запити відправляють заголовок `X-Demo-UserId`. Це дозволяє візуально демонструвати блокування операцій для невласників інцидентів.

### 4. Захист від помилок конфігурації безпеки (Security Misconfiguration)
* **HTTP безпекові заголовки**: Додано HTTP-заголовки захисту на бекенді через Express middleware:
  - `X-Content-Type-Options: nosniff` — запобігає MIME sniffing.
  - `X-Frame-Options: DENY` — захист від clickjacking.
  - `Referrer-Policy: no-referrer` — приховує джерело переходу.
* **Приховання детальних помилок**: У `errorHandler.middleware.ts` налаштовано перевірку середовища (`process.env.NODE_ENV === "production"`). У режимі production детальні повідомлення про внутрішні помилки бази даних SQLite (наприклад, UNIQUE чи CHECK constraint failed) замінюються на узагальнене повідомлення для захисту конфіденційної структури БД.
