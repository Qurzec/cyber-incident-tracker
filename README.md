# Лабораторна робота №3: Веб-застосунок "Трекер інцидентів кібербезпеки" (Варіант 2)

Цей проєкт є інтегрованим веб-застосунком для реєстрації та відстеження інцидентів кібербезпеки, який складається з клієнтської частини (**Frontend**) та серверної частини (**Backend API** на TypeScript з базою даних SQLite).

---

## Структура проєкту

Проєкт розділений на два основні компоненти:

* **[frontend/](file:///home/manjaro/projects/lab3/frontend/)**: Клієнтська частина застосунку (чистий HTML, CSS та JavaScript). Взаємодіє з сервером через HTTP-запити (`fetch`).
* **[backend/](file:///home/manjaro/projects/lab3/backend/)**: Серверна частина (Node.js + Express + TypeScript + SQLite). Надає REST API для керування користувачами та інцидентами, реалізована за трирівневою архітектурою (роути -> сервіси -> репозиторії).

---

## Як запустити застосунок

Для повноцінної роботи потрібно одночасно запустити бекенд та фронтенд.

### Крок 1: Запуск Бекенд-сервера (API)

1. Відкрийте термінал та перейдіть у папку `backend`:
   ```bash
   cd backend
   ```
2. Встановіть необхідні залежності:
   ```bash
   npm install
   ```
3. Виконайте ініціалізацію та наповнення бази даних тестовими даними:
   ```bash
   npx tsx src/db/seed.ts
   ```
4. Запустіть сервер у режимі розробки:
   ```bash
   npm run dev
   ```
   *Сервер запуститься за адресою: `http://localhost:3000`.*

### Крок 2: Запуск Фронтенду (UI) через термінал

Для запуску статичного фронтенду на порту **5500** виконайте одну з наступних команд:

* **Варіант А (через Node.js / npx)**:
  ```bash
  npx http-server frontend -p 5500
  ```
  *(або перейдіть у папку `frontend` та виконайте `npx http-server -p 5500`)*

* **Варіант Б (через Python)**:
  ```bash
  cd frontend
  ```
  ```bash
  python3 -m http.server 5500
  ```

Після цього відкрийте у браузері адресу: `http://localhost:5500` (або `http://127.0.0.1:5500`).

## Реалізована функціональність (Лабораторна робота №3)

### Серверна частина (Backend) — Рівень "На Відмінно":
* **Мова та збірка**: Повністю написаний на **TypeScript**, налаштована компіляція в JavaScript (папка `dist`) та перевірка стилю коду через ESLint + Prettier.
* **Архітектура**: Чиста трирівнева архітектура (маршрути -> сервіси -> репозиторії) з підключенням реляційної бази даних **SQLite** за допомогою сирих SQL-запитів (без ORM та параметризованих запитів).
* **Схема бази даних та міграції**:
  - Створено схему з 3 таблиць (`Users`, `Incidents`, `IncidentComments`) із констрейнтами (`CHECK`, `UNIQUE`, `NOT NULL`) та зовнішніми ключами (`FOREIGN KEY` з правилами `ON DELETE CASCADE / RESTRICT`).
  - Реалізовано автоматичне виконання міграцій з папки `migrations/` на старті та фіксацію застосованих файлів у таблиці `schema_migrations`.
* **Додаткові REST-можливості**:
  - Фільтрація, сортування та пагінація інцидентів на рівні запитів до БД.
  - Отримання пов'язаних коментарів (ендпоінт із `JOIN` з `Users`).
  - Аналітичне резюме інцидентів (агрегації `COUNT` та `GROUP BY`).
  - Демонстраційний вразливий до SQL Injection маршрут пошуку через конкатенацію рядків.
  - Часткове оновлення даних через `PATCH`.

### Клієнтська частина (Frontend):
* Відображення списку інцидентів у вигляді таблиці.
* Інтерактивна форма для додавання та редагування інцидентів з локальною валідацією полів.
* Синхронізація з бекендом у реальному часі через `fetch` (у разі недоступності сервера передбачено автоматичний перехід на `localStorage` браузера).
